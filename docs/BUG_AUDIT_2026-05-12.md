## Befunde (mindestens 10)

| Nr. | Priorität | Bug | Evidenz / Repro |
|---|---|---|---|
| 1 | **P0** | **A11y-Pipeline lokal defekt**: `npm run lint:a11y` bricht in dieser Umgebung hart ab, weil die benötigte System-Lib `libatk-1.0.so.0` fehlt. Damit ist A11y lokal nicht verifizierbar. | Repro: `npm run lint:a11y` → Puppeteer/Chrome start fail (`Code: 127`, missing shared library). |
| 2 | **P1** | **Release-Audit fällt hard-fail, wenn Production nicht erreichbar ist** (`fetch failed`). Das blockiert den Gate auch bei ansonsten grünem Build/Lint. | Repro: `npm run audit:release:json` → `overallStatus: fail`, check `production-headers` fail. |
| 3 | **P1** | **PDF-QA ist unvollständig ohne `pdfinfo`**: Seitenzahl-/Titel-/A4-Prüfung wird übersprungen statt verpflichtend geprüft. | Repro: `npm run audit:release:json` → `pdf-manifest` WARN: `pdfinfo is unavailable... checks were skipped`. |
| 4 | **P1** | **A11y-Script hat Linux-Library-Dependency-Lücke**: `findChromeExecutable()` sucht Playwright/macOS-Binaries, aber kein Guard für fehlende Linux-Runtime-Libs; dadurch reproduzierbarer Runtime-Crash statt kontrollierter Degradation. | Codepfad in `scripts/run-a11y-check.mjs` (`findChromeExecutable`, dann direkter pa11y-Run). |
| 5 | **P2** | **Release-Audit koppelt lokale Qualität mit externer Verfügbarkeit**: Ein transienter Netzausfall auf `https://bipolarsite.netlify.app` erzeugt false-negative Release-Entscheidung. | `audit:release:json` Ergebnis: alle lokalen Checks pass/warn, nur Production-Header unreachable → Gesamtstatus fail. |
| 6 | **P2** | **A11y-Check bindet festen Port `8080`** und kann bei Portkonflikten fehlschlagen (nicht konfigurierbar per Env). | `targetUrl` und `http-server ... -p 8080` sind hart kodiert in `scripts/run-a11y-check.mjs`. |
| 7 | **P2** | **A11y-Server-Readiness prüft nur `response.ok`**: Bei validem lokalen Reachability-Szenario mit nicht-2xx-Status wird fälschlich „nicht verfügbar“ angenommen; das kann zu unnötigen Timeouts führen. | `canReach()` gibt nur bei `response.ok` true zurück; `waitForServer()` hängt davon ab. |
| 8 | **P3** | **Release-Doku driftet gegenüber realer Infrastruktur**: historischer Hinweis „PDF-QA in CI behoben“ ist lokal nicht haltbar, da `pdfinfo` optional bleibt und Checks übersprungen werden. | Vergleich der aktuellen Audit-Ausgabe (WARN) mit älterem Audit-Dokument zeigt Drift im Ist-Zustand. |
| 9 | **P3** | **Fehlende Differenzierung „infra-fail vs. product-fail“ im Release-Audit**: Network-/Dependency-Fehler werden gleichwertig als Produkt-Bug gewertet (hart fail). | `production-headers` und Toolchain-Abhängigkeiten dominieren `overallStatus`, obwohl Produktchecks grün sind. |
| 10 | **P3** | **A11y-Fehlerdiagnose zu grob**: Bei Browser-Launch-Problemen wird nur generischer Fallback-Text ausgegeben, kein klarer remediation-Hinweis (z. B. benötigte Linux-Pakete). | Catch-Block in `scripts/run-a11y-check.mjs` loggt nur generische Meldung + Raw-Error. |

## Empfohlene nächste Schritte
1. **P0/P1 zuerst**: Container-/CI-Basis um fehlende Chrome-Libs ergänzen oder auf Playwright-Headless-Stack ohne System-Chrome umstellen.
2. **Audit-Resilienz**: `production-headers` als separaten Gate führen (z. B. `warn` bei Reachability-Fail, `fail` nur bei bestätigter Header-Regression).
3. **PDF-QA harden**: `pdfinfo` als verpflichtende Dependency (CI + lokale Doku) oder klarer Fallback mit Fail-Policy.
4. **Script-Härtung**: konfigurierbarer Port, bessere Readiness-Heuristik, actionable Error-Messages.
