# Bug-Audit (mindestens 10 Befunde)

**Datum:** 2026-05-09  
**Methode:** Repo-Review + Release-Audit-Lauf (`npm run audit:release:ci`).

## 1) Release-Audit kann PDF-QA nicht vollständig prüfen ohne `pdfinfo`
- **Symptom:** PDF-Seitenzahl-/Titel-/A4-Checks werden übersprungen.
- **Impact:** Fehlerhafte PDF-Metadaten oder falsche Seitenangaben können unentdeckt bleiben.
- **Evidenz:** Audit-Warnung `spawn pdfinfo ENOENT`.

## 2) Browser-Release-Gate ist nicht automatisiert
- **Symptom:** Wichtige Zielbrowser (iPhone Safari/Chrome, Desktop Firefox, Android Chrome) müssen manuell getestet werden.
- **Impact:** Regressions-Risiko vor Release, wenn manuelle Checks ausfallen.
- **Evidenz:** `browser-hand-off` ist im Release-Audit weiterhin `warn`.

## 3) NPM-Umgebungswarnung bei jedem Audit-Lauf
- **Symptom:** `npm warn Unknown env config "http-proxy"`.
- **Impact:** CI/Local Runs sind noisy; zukünftige npm-Versionen könnten Verhalten ändern.
- **Evidenz:** Ausgabe beim Start von `npm run audit:release:ci`.

## 4) CTA-Überladung auf der Startseite
- **Symptom:** Im oberen Seitenbereich konkurrieren ~11 Optionen gleichzeitig.
- **Impact:** Kognitive Last in einer Krisen-/Belastungssituation steigt.
- **Evidenz:** Zählung im Audit-Dokument zur Hero-Konzentration.

## 5) Doppelte Werkzeuge-Einstiege auf derselben Seite
- **Symptom:** Werkzeuge sind als Entry-Path und zusätzlich in `.tools-highlight` prominent verlinkt.
- **Impact:** Redundanz ohne klare Priorisierung; lenkt vom geführten Einstieg ab.
- **Evidenz:** Sub-Befund „Punkt 13 (Doppelung Werkzeuge)".

## 6) Modul-Grid ohne klaren „Anfangen hier“-Fokus
- **Symptom:** Alle 8 Module erscheinen gleichrangig.
- **Impact:** Neue Nutzer:innen ohne Orientierung müssen selbst priorisieren.
- **Evidenz:** Sub-Befund „Punkt 10 (Wissensreise vs. Portal)".

## 7) Hero-Subtitle zu lang/überfrachtet
- **Symptom:** ~50-Wörter-Satz mit mehreren Themenclustern.
- **Impact:** Schlechtere Lesbarkeit auf mobil und unter Stress.
- **Evidenz:** Sub-Befund „Punkt 9 (kürzere Blöcke)".

## 8) SOS-Banner unterbricht Lesefluss im Startseiten-Aufbau
- **Symptom:** Roter Notfallblock zwischen Hero und Intro.
- **Impact:** Inhaltlicher Flow wird unterbrochen; kann Reizdichte erhöhen.
- **Evidenz:** Sub-Befund „Punkt 14 (Reizdichte)".

## 9) Hub Modul 8: SOS-Information redundant zwischen Hero und Pathways
- **Symptom:** Urgent-Note doppelt Sicherheitskommunikation, obwohl Pathways bereits Akut-Hierarchie zeigen.
- **Impact:** Zusätzliche visuelle Last ohne klaren Mehrwert.
- **Evidenz:** Befund Modul 8 + Empfehlung R5(c).

## 10) Lokale A11y-Prüfung auf Apple-Silicon nicht robust
- **Symptom:** `npm run lint:a11y` kann lokal mit `spawn Error -86` scheitern.
- **Impact:** Zugänglichkeitsprüfungen werden lokal ausgelassen oder uneinheitlich durchgeführt.
- **Evidenz:** Offener P3-Punkt im Technical Backlog.

---

## Kurzfazit
Die kritischsten „operativen“ Bugs sind (1) fehlendes `pdfinfo` in der QA-Kette und (2) nicht automatisierte Browser-Freigabe. Die übrigen Befunde sind v. a. UX-/Informationsarchitektur-Bugs mit direktem Einfluss auf Orientierung und kognitive Last.
